# Deliverable Templates

> **Running this skill's scripts:** always `node .claude/skills/deliverable-templates/scripts/<script>.mjs …` from the workspace root (every
> Bash call starts there). Do **not** build the path from the absolute base directory shown when the skill loads —
> `node "C:/…/.claude/skills/…"` is not pre-approved and stops for an approval; the relative form is.

> Complements `sap-architecture` (source of gate answers) and `sap-unit-testing` (test content).
> Templates live in `references/`; finished documents go to `<app>/deliverables/`.
> **TDD:** never compose it by hand in one `Write` — run `scripts/tdd-scaffold.mjs <app>` (facts filled from
> the code, `✍️ TO WRITE` blocks for the narrative), fill one section per `Edit`, then `scripts/tdd-scaffold.mjs <app> --check`
> until exit 0. A single 40–80 KB `Write` exceeds the output limit on bigger apps and saves nothing.

Fill every `{{placeholder}}` (Application Architecture) / `✍️ TO WRITE` block (TDD scaffold) from the gate answers recorded in
`Application-Architecture.md`, the Requirement Register and the code. Never leave a placeholder or marker in a finished document.

## Gate answers → Unit Testing Document

Backend choice drives §3 CAP cases (Jest) and whether mock or in-memory sqlite is the env (§2). Floorplan drives §5 OPA5 journeys. The data-model/actions gate drives the computed-field boundary and transition cases. Auth drives the §3 authorization cases. Always include the required test-case table (`ID | Layer | Scenario | Preconditions | Input | Expected | Type`) and the coverage targets from `sap-unit-testing`.

## Quality bar

- Every section present; no empty headings, no leftover placeholders or `✍️ TO WRITE` markers — proven by `tdd-scaffold.mjs --check` (exit 0).
- The generated Mermaid diagrams (§3.4, §13.4) stay Mermaid: correct or extend them in place (an external system the
  project does not declare, a business step), never replace them by prose or an image — `--check` fails a §3.4 without
  a `mermaid` block. They render on GitHub, Azure DevOps, GitLab and Confluence (Mermaid macro), and in VS Code / SAP
  Business Application Studio with a Mermaid preview extension. Node labels: plain text, `<br/>` for a line break, no
  double quotes, semicolons or `#` inside a label.
- §13.1 of the TDD always states the **chosen pattern, its rationale, and the rejected alternatives** (this is the Clean Core decision record).
- §1.4 of the TDD lists **every assumption surfaced at a gate** with the chosen default — this is the audit trail of the interactive session.
- The Unit Testing Document's traceability appendix maps requirement → TDD element → test ID(s).
